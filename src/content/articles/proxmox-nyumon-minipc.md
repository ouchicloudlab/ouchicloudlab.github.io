自宅サーバーを本格的に楽しむなら、避けて通れないのが **仮想化** です。1台のミニPCの中に、複数の仮想マシン（VM）や軽量コンテナ（LXC）を同居させ、「NAS用」「メディアサーバー用」「実験用」と役割を分けて動かせます。

その仮想化基盤として自宅サーバー界隈で圧倒的な定番が、無料で使える **Proxmox VE** です。この記事では、ミニPC1台でProxmoxを始める手順を、初心者がつまずきやすいポイントとあわせて解説します。

<!-- AD -->

## Proxmox VEとは

Proxmox VE（Virtual Environment）は、Debian Linuxをベースにした**無料のオープンソース仮想化プラットフォーム**です。ブラウザから使えるWeb管理画面が付属し、VMとコンテナの両方を1つの画面で管理できます。

- **VM（仮想マシン）**：WindowsやLinuxを丸ごと動かせる。用途を強く分離したいとき向き
- **LXCコンテナ**：Linux環境を軽量に動かせる。省メモリで多数動かせる

商用のVMware系が有料化・変更で揺れる中、無料で情報も豊富なProxmoxは、2026年も自宅サーバーの第一候補です。

## 準備するもの

1. **ミニPC**（メモリ16GB以上を推奨。VMを複数動かすなら余裕を持って）
2. **8GB以上のUSBメモリ**（インストール用）
3. **有線LAN接続**（安定運用のため無線より有線を推奨）
4. 別のPC（Web管理画面にアクセスする用）

> メモリはProxmox運用で最も効いてくる要素です。8GBでも始められますが、VM/コンテナを増やすとすぐ足りなくなります。増設できる機種なら16〜32GBにしておくと快適です。

## インストールの手順

### 1. インストーラーを用意する

Proxmox公式サイトから「Proxmox VE」のISOイメージをダウンロードし、**Rufus**（Windows）や **balenaEtcher** などのツールでUSBメモリに書き込みます。

### 2. USBから起動してインストール

ミニPCにUSBを挿して起動し、BIOS/UEFIで**USBブート**を選択します。画面の案内に従い、インストール先ディスク・タイムゾーン（Asia/Tokyo）・rootパスワード・固定IPアドレスを設定します。

- **固定IP**は必ず控えておきましょう（後で管理画面にアクセスするのに使います）。
- インストールは10分ほどで完了します。

### 3. Web管理画面にアクセス

インストール後、別のPCのブラウザから `https://（設定したIP）:8006` にアクセスします。自己署名証明書の警告が出ますが、そのまま進んでOK。ユーザー名 `root` と設定したパスワードでログインできれば成功です。

## 最初のコンテナ（LXC）を作ってみる

まずは軽量なLXCコンテナで感覚をつかむのがおすすめです。

1. 管理画面でLXCテンプレート（例：Debian や Ubuntu）をダウンロード
2. 「CTを作成」からコンテナを新規作成（CPU・メモリ・ディスクを割り当て）
3. 起動してコンソールからログイン

これだけで、独立したLinux環境が1つ手に入ります。ここに Pi-hole や Nextcloud などを入れていく、というのが自宅サーバーの基本的な広げ方です。

## インストール直後にやる4つの設定

インストールが終わってログインしたら、**最初に済ませておくべき設定**があります。ここを飛ばすと後で必ずつまずきます。

### 1. 「有効なサブスクリプションがありません」の対処

ログインするたびに表示される警告と、`apt update` でのリポジトリエラーです。Proxmox VE は無料で使えますが、標準では**有料サブスクリプション向けのリポジトリ**を参照しているため、更新時にエラーになります。

無料版（no-subscription）のリポジトリに切り替えます。

```bash
# エンタープライズリポジトリを無効化
sed -i 's/^deb/#deb/' /etc/apt/sources.list.d/pve-enterprise.list

# 無料版リポジトリを追加（バージョン名は環境に合わせる）
echo "deb http://download.proxmox.com/debian/pve bookworm pve-no-subscription" \
  > /etc/apt/sources.list.d/pve-no-subscription.list

apt update && apt full-upgrade -y
```

ログイン時のダイアログ自体は消えませんが、**動作には一切影響ありません**。無料で使い続けて問題ないライセンスです。

### 2. バックアップの保存先を決める

Proxmox の最大の利点は、**VM/コンテナを丸ごとバックアップ・復元できる**ことです。ただし初期状態ではバックアップ先がローカルディスクのみで、本体が壊れたら一緒に失われます。

「データセンター → ストレージ」で、NASや外付けディスクを **NFS** または **SMB/CIFS** で追加し、そこをバックアップ先に指定してください。

### 3. 定期バックアップのスケジュールを組む

「データセンター → バックアップ → 追加」から設定します。おすすめの初期設定は次のとおりです。

| 項目 | 推奨設定 | 理由 |
|---|---|---|
| 実行時間 | 深夜（例：03:00） | 負荷が高くなるため |
| モード | スナップショット | 稼働したままバックアップできる |
| 圧縮 | ZSTD | 速度と圧縮率のバランスが良い |
| 保持数 | 直近3〜7世代 | 容量と復旧可能性のバランス |

**復元も一度は試してください。** バックアップは「取れていること」ではなく「戻せること」が目的です。

### 4. 電源復帰時の自動起動とVMの自動起動

ミニPC側のBIOSで「Restore on AC Power Loss → Power On」を設定し、Proxmox側では各VM/コンテナのオプションで「起動時に開始」を有効にします。これをやっておかないと、**停電後にサーバーは戻ってきません**。

## VMとLXCコンテナ、どちらを使うべきか

Proxmox では2つの方式を選べます。使い分けの基準は明確です。

| 観点 | LXCコンテナ | VM（仮想マシン） |
|---|---|---|
| メモリ消費 | 少ない（数十MB〜） | 多い（最低512MB〜1GB） |
| 起動速度 | 数秒 | 数十秒 |
| 分離の強さ | 弱め（ホストとカーネル共有） | 強い（完全に独立） |
| Windows | **不可** | 可能 |
| Docker を動かす | 可能だが設定が必要 | **推奨** |
| GPUの利用 | 共有しやすい | パススルー設定が必要 |
| スナップショット | 可能 | 可能 |

**基本方針**：単機能のLinuxサービス（Pi-hole、Uptime Kuma など）は **LXC**、Docker をまとめて動かす環境や Home Assistant OS は **VM**、という切り分けが定番です。

### Docker は LXC と VM のどちらで動かすか

自宅サーバーで最もよく議論される点です。

- **LXC上のDocker**：メモリ効率が良く、リソースを節約できる。ただし「特権コンテナ」設定やネスト設定が必要な場合があり、非特権コンテナでは一部のイメージが動かないことがあります。
- **VM上のDocker**：素直に動き、トラブルが少ない。Proxmox 公式もこちらを推奨しています。メモリを1〜2GB余分に使う代わりに、**ハマる時間を買える**構成です。

**初心者には VM 上での Docker をおすすめします。** 動かないときの原因切り分けが格段に簡単だからです。

## ストレージ構成の基礎（local と local-lvm の違い）

インストール直後、ストレージが2つ見えて混乱しがちです。

- **local**：ISOイメージ、コンテナテンプレート、バックアップファイルを置く場所
- **local-lvm**：VMやコンテナの仮想ディスク本体を置く場所

「ISOをアップロードしようとしたら local-lvm が選べない」というのは、この役割分担によるものです。

ディスクを1本しか積んでいない場合、**システムとデータが同居**します。M.2スロットが2つある機種なら、システム用とデータ用を分けておくと、後の管理が楽になります。

## 省電力設定を忘れずに

Proxmox はサーバー用途を前提としているため、初期状態では**省電力よりも性能を優先**する設定になっています。24時間稼働の自宅サーバーでは、ここを調整すると数W下がります。

```bash
# CPUの周波数制御を省電力寄りにする
apt install cpufrequtils
echo 'GOVERNOR="powersave"' > /etc/default/cpufrequtils
systemctl restart cpufrequtils

# 現在の状態を確認
cat /sys/devices/system/cpu/cpu0/cpufreq/scaling_governor
```

あわせてBIOSでC-Stateを有効にしてください。詳しくは [アイドル10W以下の省電力ミニPC5選](/articles/low-power-mini-pc-idle-under-10w-home-server/) の設定編にまとめています。

## そのほかつまずきやすいポイント

- **仮想化支援（VT-x/AMD-V）が無効**：VMが作成できない、または起動しない場合はBIOSで有効化します。
- **メモリの割り当てすぎ**：全VM/CTの合計が物理メモリを超えると、ホストごと不安定になります。ホスト自身のために **2GB程度は空けておいてください**。
- **ブリッジ設定の理解**：`vmbr0` が仮想スイッチにあたります。VMやコンテナはこれに繋がることで家庭内LANに参加します。ここを誤って変更すると管理画面ごと繋がらなくなるため、リモートで作業する際は特に注意してください。
- **スナップショットを撮ったまま放置**：スナップショットは差分を保持し続けるため、長期間放置すると容量を圧迫します。検証が終わったら削除しましょう。
- **root で全部やってしまう**：慣れてきたら、日常操作用のユーザーを作って権限を分けると安全です。

> **編集部メモ**：最初から完璧な構成を目指さず、「コンテナを1つ作る→壊す→また作る」を繰り返して慣れるのが上達の近道です。**スナップショットを撮ってから作業する**習慣をつけると、失敗を恐れずに実験できます。これがProxmoxを使う最大の心理的メリットです。

## よくある質問

**Q. Proxmox は無料で使い続けられますか？**
使えます。有料サブスクリプションは、企業向けの安定版リポジトリとサポートを得るためのものです。個人利用では no-subscription リポジトリで問題なく運用できます。

**Q. ミニPC1台にProxmoxを入れると、性能が落ちませんか？**
仮想化のオーバーヘッドはありますが、LXCコンテナならほぼ無視できる程度です。VMでも数%程度で、自宅サーバー用途で体感できる差にはなりにくいでしょう。それよりも「壊しても戻せる」利点の方が大きいと考えています。

**Q. メモリは何GB必要ですか？**
ホスト自身に2GB、そこに動かすサービス分を足します。LXCで軽量サービスを5〜6個なら8GBでも回りますが、**Immich や Jellyfin をVMで動かすなら16GB**は欲しいところです。

**Q. Proxmox を入れずに Ubuntu + Docker ではダメですか？**
問題ありません。むしろシンプルで、リソースの無駄も少ない構成です。Proxmox を選ぶ理由は「スナップショットで戻せること」と「Home Assistant OS のようなVM前提のソフトを同居させられること」の2点です。この2つが不要なら、Ubuntu + Docker で十分です。

**Q. クラスタを組むべきですか？**
自宅サーバーでは、まず1台で運用することをおすすめします。クラスタは3台以上が前提（2台構成では正常な多数決が成立しない）で、消費電力も台数分かかります。

## まとめ

- Proxmox VE は無料で使える自宅サーバーの定番仮想化基盤
- インストール直後に **no-subscription リポジトリへの切り替え・バックアップ先の設定・定期バックアップ・自動起動**の4点を済ませる
- **単機能サービスはLXC、DockerやHome Assistantは VM** が定番の使い分け
- Docker を動かすなら、初心者は**VM上**が無難（トラブルが少ない）
- ホスト用に**メモリを2GB空けておく**
- スナップショットを撮ってから作業する習慣が、上達を早める

仮想化を覚えると、1台のミニPCの活用度が一気に上がります。次は [Dockerで動かす自宅サービス10選](/articles/docker-self-hosting-10/) で、実際に何を動かすかを選んでみてください。省電力なミニPC選びは [自宅サーバー向けミニPCおすすめ5選](/articles/mini-pc-osusume-2026/) をどうぞ。
