## Googleフォトの容量制限に悩んでいませんか

Googleフォトの無料枠は15GBしかなく、スマホで撮った写真や動画はあっという間に上限に達します。有料プランへの加入を続けるか、別のクラウドサービスに乗り換えるか——そんな悩みを解決してくれるのが、オープンソースの自己ホスト型写真管理ツール「Immich」です。

Immichはスマホアプリからの自動バックアップ、顔認識、地図表示、共有アルバムなど、Googleフォトに匹敵する機能を無料かつプライバシーを守った状態で使えます。本記事では、自宅サーバーやNASにImmichを構築する手順と、運用のコツを紹介します。

## Immichとは何か

Immichは2022年頃から開発が始まったオープンソースプロジェクトで、Docker Composeを使って自宅のサーバーやNASに簡単に導入できます。主な特徴は以下の通りです。

- iOS/Android向け公式アプリがあり、バックグラウンドで自動バックアップが可能
- 顔認識・オブジェクト検出による写真の自動タグ付け（AI処理はローカルで完結）
- 地図表示、タイムライン表示、アルバム共有などGoogleフォトに近いUI
- 開発が非常に活発で、月単位で機能追加やバグ修正が行われている

一方で、まだ発展途上のプロジェクトである点には注意が必要です。メジャーバージョンアップ時にデータベースの互換性が変わることがあり、アップデート前のバックアップは必須です。

## 構築に必要な機材の目安

Immichは写真のサムネイル生成やAI解析でそれなりにCPU・メモリを使います。快適に運用するための目安は次の通りです。

- **CPU**: Intel N100搭載ミニPCなど、近年の省電力CPUで十分動作します
- **メモリ**: 8GB以上を推奨。写真枚数が数万枚を超えるなら16GB前後が安心です
- **ストレージ**: 写真・動画の保存用に大容量HDD/SSD、加えてサムネイル用に高速なSSDがあると快適
- **NAS**: Synology・QNAPなどでもDocker（Container Manager）対応モデルなら導入可能

すでにNASやミニPCで自宅サーバーを運用している方は、追加のコンテナとしてImmichを載せるだけで始められます。

## 必要なストレージ容量を先に計算する

構築の前に、**何TB必要か**を出しておきましょう。ここを見誤ると、半年後にディスクを買い足すことになります。

| データ | 1枚/1本あたり | 1,000件で |
|---|---|---|
| スマホ写真（JPEG） | 3〜5MB | 約4GB |
| スマホ写真（HEIC） | 1.5〜3MB | 約2GB |
| 一眼レフ RAW | 25〜45MB | 約35GB |
| スマホ動画（1080p・1分） | 約130MB | — |
| スマホ動画（4K・1分） | 約350MB | — |

**Immich はサムネイルとプレビューを別途生成します。** その分として、**元データの10〜20%程度**を上乗せしてください。写真2万枚（約80GB）＋動画300本（約100GB）なら、`180GB × 1.2 ≒ 216GB` が最低ライン。ここに数年分の増加を見込んで、**1TB程度**を確保しておくと安心です。

## 構築手順（Docker Compose）

### 1. 事前準備

Docker と Docker Compose がインストールされている環境を用意します。Ubuntu Server や Debian を入れたミニPC、あるいはNASのコンテナ機能を使うのが一般的です。

### 2. 公式のcompose定義を取得する

Immich 公式では、必要な `docker-compose.yml` と `.env` のサンプルが配布されています。

```bash
mkdir -p /srv/docker/immich && cd /srv/docker/immich
wget -O docker-compose.yml https://github.com/immich-app/immich/releases/latest/download/docker-compose.yml
wget -O .env https://github.com/immich-app/immich/releases/latest/download/example.env
```

### 3. .env を編集する

最低限、次の項目を自分の環境に合わせます。

```bash
# 写真・動画の保存先（大容量ストレージのパスを指定）
UPLOAD_LOCATION=/mnt/photos/immich

# データベースの保存先（できればSSD上に）
DB_DATA_LOCATION=/srv/docker/immich/postgres

# タイムゾーン
TZ=Asia/Tokyo

# データベースのパスワード（必ず変更する）
DB_PASSWORD=ここに強固なパスワード
```

**重要な注意点**：`UPLOAD_LOCATION` を後から変更するのは非常に面倒です。**最初に「今後数年使えるパス」を決めてください**。また、ここをNFS/SMBでマウントしたネットワーク先にすると、パフォーマンスと安定性が落ちることがあります。可能な限り**ローカルディスクを指定**してください。

### 4. コンテナ起動

```bash
docker compose up -d
```

初回起動時は、サーバー本体・PostgreSQL・Redis・機械学習用コンテナのダウンロードに時間がかかります（合計で数GB）。起動後、ブラウザで `http://サーバーのIP:2283` にアクセスすると初期設定画面が表示されます。

**最初に作成したアカウントが管理者**になります。家族分のアカウントは、管理画面から後で追加できます。

### 5. スマホアプリの設定

公式アプリをインストールし、サーバーURLとログイン情報を入力すれば自動バックアップが始まります。

設定で確認しておきたい項目は次の3つです。

- **バックアップ対象のアルバム**：カメラロールだけか、スクリーンショットも含めるか
- **Wi-Fi接続時のみバックアップ**：モバイル通信量を節約したい場合は必ずON
- **バックグラウンドバックアップ**：iOS では制約があり、アプリを開いたときにまとめて処理されることがあります

外出先からも使いたい場合は、**Tailscale と組み合わせるのが安全**です。ポート開放によるインターネット直接公開は、写真という極めてプライベートなデータを扱う以上おすすめしません。設定方法は [Tailscaleで自宅サーバーに外部から安全にアクセスする設定方法](/articles/tailscale-home-server-remote-access-2026/) をご覧ください。

## 初回インポートは「寝る前に始める」

導入して最初に驚くのが、**初回取り込み時の負荷**です。

Immich は取り込んだ全写真に対して、サムネイル生成・顔認識・被写体のタグ付けといった機械学習処理を実行します。これがCPUを長時間占有します。

| 写真枚数 | 省電力ミニPC（N100級）での目安 |
|---|---|
| 5,000枚 | 数時間 |
| 20,000枚 | 半日〜1日 |
| 50,000枚以上 | 数日 |

**この間、ミニPCのCPUはほぼ100%で張り付き、消費電力も上がります。** 途中で止めても再開できるので、慌てる必要はありません。**寝る前や外出前に開始する**のが現実的な進め方です。

処理が重すぎる場合は、管理画面の「ジョブ」から機械学習系のジョブを一時停止し、まずバックアップ（写真の保存）だけを完了させてから、後日AI処理を回すという分割も可能です。

### ハードウェアアクセラレーションで軽くする

Intel の内蔵GPU（Quick Sync）を搭載したミニPCなら、動画のトランスコードをGPUに任せてCPU負荷を下げられます。公式が提供する `hwaccel.transcoding.yml` を読み込む設定を追加し、`/dev/dri` をコンテナに渡します。

機械学習側も同様に、OpenVINO を使った高速化に対応しています。省電力機で大量の写真を扱うなら、設定する価値は大きい項目です。

## Googleフォトからの移行手順

### 1. Google Takeout でエクスポートする

Google の [Takeout](https://takeout.google.com/) から「Googleフォト」を選択してエクスポートします。データ量が多いと、2GB〜50GB単位の複数ファイルに分割され、生成に数時間〜数日かかります。

### 2. メタデータの問題に注意する

**Takeout の最大の落とし穴**がここです。エクスポートされたデータは、写真本体（JPG）と、撮影日時・位置情報を含むメタデータ（JSONファイル）が**分離した状態**で出力されます。

そのまま Immich に取り込むと、**すべての写真の日付が「取り込んだ日」になってしまい、タイムラインが崩壊します**。

これを防ぐには、取り込み前にJSONのメタデータを写真本体に書き戻す必要があります。`google-photos-migrate` や `immich-go` といったツールが、この処理を自動化してくれます。**必ず少量のテストデータで試してから、全件を処理してください。**

### 3. 取り込む

サーバー上に配置したファイルは、公式CLIツールでアップロードできます。

```bash
# 例：ディレクトリを指定してアップロード
immich upload --recursive /path/to/takeout/photos
```

### 4. 並行運用の期間を設ける

**移行が完了した確信が持てるまで、Googleフォト側は消さないでください。** 枚数の突合、日付の整合、動画の再生確認を済ませ、1〜2か月は並行運用することをおすすめします。

## 運用時の注意点

### バックアップは2種類必要

Immich の魅力は自由度の高さですが、裏を返せば「壊れたら自己責任」です。**バックアップ対象は2つある**点に注意してください。

1. **写真データ本体**（`UPLOAD_LOCATION`）— 容量は大きいが、ファイルコピーで済む
2. **データベース**（PostgreSQL）— アルバム構成・顔情報・共有設定がここにある

データベースのバックアップは、ファイルをそのままコピーするのではなく、**dumpを取るのが正しい方法**です。

```bash
# データベースのダンプを取得（毎日実行する例）
docker exec -t immich_postgres pg_dumpall --clean --if-exists \
  --username=postgres | gzip > /mnt/backup/immich-db-$(date +%F).sql.gz
```

写真本体は `rsync` で外付けHDDへ同期します。3-2-1ルール（3つのコピー、2種類の媒体、1つは別の場所）を意識すると安心です。

**写真データだけを守ってDBを失うと、アルバムや共有設定は消えますが、写真そのものは残ります。** 逆にDBだけあっても写真は戻りません。優先順位は写真本体が上です。

### アップデートは慎重に

Immich は開発が非常に活発で、月単位で機能追加とバグ修正が行われています。その反面、**メジャーバージョンアップで破壊的変更が入ることがあります**。

- 更新前に必ず**リリースノートの「Breaking Changes」を確認**する
- **DBのダンプを取ってから**更新する
- Proxmox 上で運用しているなら、**スナップショットを撮ってから**実行する（数秒で戻せます）
- `latest` タグでの自動更新は避け、**手動でタイミングを選ぶ**

### 家族での利用

Immich はマルチユーザーに対応しており、家族それぞれのアカウントを作成して共有アルバムを運用できます。**「Partner Sharing」機能**を使うと、パートナーの写真を自分のタイムラインに統合して表示できます。Googleフォトの家族共有に近い使い方が可能です。

## コストを比較してみる

Googleフォトの2TBプラン（月額1,300円程度）と比較します。

| 項目 | Googleフォト 2TB | Immich（自宅） |
|---|---|---|
| 初期費用 | 0円 | ミニPC 35,000円＋HDD 12,000円 |
| 年間費用 | 15,600円 | 電気代 約2,700円 |
| 3年間の合計 | 46,800円 | 55,100円 |
| 5年間の合計 | 78,000円 | 60,500円 |

**損益分岐点はおよそ4年**です。金銭面だけで見ると、それほど大きなメリットはありません。Immich を選ぶ理由は、**容量を自分で決められること**、**写真を他社に預けないこと**、そして**サービス終了や値上げの影響を受けないこと**にあります。

なお、すでに自宅サーバーを別の用途で動かしているなら、追加コストは実質ゼロです。その場合は迷わず導入する価値があります。

## よくある質問

**Q. NASのDocker機能でも動きますか？**
Container Manager（Synology）や Container Station（QNAP）を備えたモデルなら可能です。ただし、機械学習処理はCPU性能に依存するため、**ARM系CPUのエントリーモデルでは初回処理が非常に遅くなります**。Intel CPU搭載機を推奨します。

**Q. 動画も保存できますか？**
できます。ただし動画は容量を大きく消費し、再生時にトランスコードが必要になる場合はCPU負荷も高くなります。4K動画を大量に扱うなら、ストレージとハードウェアアクセラレーションの両方を検討してください。

**Q. スマホの写真を消しても大丈夫ですか？**
バックアップ完了を確認してからにしてください。Immich アプリには、バックアップ済みの写真を端末から削除する機能がありますが、**「バックアップされた」＝「バックアップのバックアップがある」ではありません**。サーバー側のディスクが壊れれば同時に失われます。端末から消すのは、サーバー側のバックアップ体制が整ってからにしましょう。

**Q. iOSのバックグラウンドバックアップが動きません**
iOS のバックグラウンド実行制限によるもので、Immich 固有の問題ではありません。アプリを定期的に開く運用にするか、Wi-Fi接続時・充電時に自動起動する設定を活用してください。

**Q. Nextcloud の写真機能と何が違いますか？**
Nextcloud は汎用のファイル同期・共有基盤で、写真はその一部です。Immich は**写真・動画に特化**しており、顔認識・被写体検索・地図表示・タイムラインといった体験がGoogleフォトに近い点が最大の違いです。

## まとめ

Immich は、Googleフォトの容量制限や将来の値上げリスクから解放されたい方にとって有力な選択肢です。

- **必要容量は「元データ × 1.2」＋数年分の余裕**で見積もる
- `UPLOAD_LOCATION` は後から変えにくい。**最初に決める**
- **初回インポートは数時間〜数日**。寝る前に始める
- Googleフォトからの移行は、**Takeout のメタデータ分離問題**に必ず対処する
- バックアップは**写真本体とデータベースの2種類**が必要
- アップデート前に**リリースノート確認とDBダンプ**を習慣化する
- 金銭的な損益分岐点は約4年。**価値は容量の自由とプライバシー**にある

まずは試験的に一部の写真フォルダから移行し、動作を確認しながら本格運用に移すのがおすすめです。動かす母艦の選び方は [自宅サーバー向けミニPCおすすめ5選](/articles/mini-pc-osusume-2026/) を参考にしてください。
