## 「RAIDを組んだから安心」が一番危ない

自宅NASを買ってRAID 1やRAID 5を組むと、「これでデータは守られた」と感じやすくなります。しかし、RAIDが守ってくれるのは**ディスクが1台壊れたときに止まらず動き続けること**だけで、誤削除やランサムウェア、火災からは守れません。

そこで使われる考え方が「3-2-1ルール」です。データのコピーを3つ持ち、2種類の媒体に分け、1つは家の外に置く。言葉にすると単純ですが、自宅NASに当てはめると「外付けHDDは何TB必要か」「家の外はポータブルHDDかクラウドか」「何日おきに入れ替えれば足りるか」といった具体的な判断が必要になります。

この記事では、RAIDがバックアップにならない理由を整理したうえで、3-2-1ルールを自宅NASで実現する組み合わせを予算別に示し、Synology の Hyper Backup や USB Copy、Linux の rsync と cron を使った自動化の手順までまとめます。

## RAIDはバックアップではない理由

RAIDとバックアップは、守る対象がまったく違います。RAIDは「今のデータ」を複数のディスクに同時に書き込む仕組みなので、**正しい変更も、間違った変更も、すべてのディスクに即座に反映されます**。

- **誤削除**: ファイルを消すと、ミラー側のディスクからも同時に消えます。RAIDには「昨日の状態」が残りません。
- **ランサムウェア**: NASの共有フォルダが暗号化されると、暗号化された状態がそのまま全ディスクに書き込まれます。
- **NAS本体の故障**: 電源回路やマザーボードが壊れると、ディスクが無事でも中身を読み出すには同じ系統の機器や復旧作業が必要になります。
- **再構築中の2台目の故障**: 同時期に買った同じロットのディスクは劣化の進み方も似ています。1台が壊れて再構築（リビルド）している最中に、高い負荷を受けたもう1台が壊れると、RAID 1やRAID 5ではデータを失います。
- **火災・盗難・落雷・水害**: NASごと失われれば、何台のディスクで冗長化していても意味がありません。

RAIDは「止まらないための仕組み」、バックアップは「戻すための仕組み」と覚えておくと混同しません。RAIDの種類ごとの実効容量はこの後の容量見積もりにも関わるので、詳しくは [NAS用HDDおすすめ比較2026 WD RedとIronWolfの違いと選び方](/articles/nas-hdd-comparison-wd-red-ironwolf/) の「RAID構成と実効容量の目安」もあわせて確認してください。

## 3-2-1ルールとは：コピー3つ・媒体2種類・1つは家の外

### コピー3つは「元データを含めて」数える

3つのコピーとは、NASにある元データ＋バックアップ2つ、という意味です。RAID 1で2台のディスクに同じデータがあっても、これは1つと数えます。前述のとおり、同じ変更が同時に反映されるからです。

### 媒体2種類は「別の筐体」と読み替える

もともとは「HDDとテープ」「HDDと光ディスク」のように記録方式を分ける意味でした。自宅NASでは、テープ装置を用意するのは現実的ではないため、**NAS本体とは別の筐体・別の電源で動く場所にコピーを置く**と読み替えるのが実用的です。NASのUSBポートにつないだ外付けHDD、2台目のNAS、クラウドは、どれもNAS本体と同時には壊れにくいという意味で条件を満たします。逆に、同じNASの中の別ボリュームや、同じRAIDの中の別フォルダは条件を満たしません。

### 1つは家の外が、家ごと失う事故への唯一の備え

火災・盗難・落雷・水害は、家の中にあるものをまとめて奪います。NASの横に外付けHDDを置いていても、同じ部屋にあれば一緒に失います。家の外のコピー（オフサイト）だけが、この種類の事故に効きます。実家や職場に預けるポータブルHDD、遠隔地の2台目NAS、クラウドストレージのいずれかで用意します。

## 方式ごとに守れる事故の違い

どのバックアップ方式で、どの事故から戻せるのかを一覧にすると、3つを組み合わせる意味がはっきりします。

| 事故の種類 | RAIDのみ | NASのスナップショット | 外付けHDD（世代あり） | 家の外のコピー |
|---|---|---|---|---|
| ディスク1台の故障 | 守れる | 守れない（RAIDなしなら同じディスク上にある） | 守れる | 守れる |
| 誤削除・上書き | 守れない | 守れる | 守れる | 守れる（入れ替え時点まで） |
| ランサムウェア | 守れない | 条件付き（管理者権限を奪われると消される） | 条件付き（常時接続だと一緒に暗号化されうる） | 守れる（ネットから切り離されていれば） |
| NAS本体の故障 | 守れない | 守れない | 守れる | 守れる |
| 火災・盗難・落雷 | 守れない | 守れない | 守れない（同じ部屋にある） | 守れる |

表を縦に見ると、すべての行で「守れる」になる方式は1つもありません。スナップショットは誤削除に強いがNASごと失えば無力、外付けHDDは手軽だが家の事故には無力、家の外のコピーは強いが入れ替えた時点より新しいデータは戻らない。**3-2-1ルールは、弱点の違う方式を重ねて穴をふさぐ考え方**だと言えます。

## まず必要な容量を見積もる

機材を選ぶ前に、バックアップ先に何TB必要かを計算します。式は次のとおりです。

```
必要容量 ＝（今のNAS使用量 ＋ 年間の増加量 × 使う年数）×（1 ＋ 世代の上乗せ率）
```

世代の上乗せ率は、何日分の履歴を残すかと、日々どれだけファイルが書き換わるかで変わります。写真や動画のように「追加はされるが書き換えは少ない」データなら1〜2割程度が目安です。仕事のファイルを頻繁に上書きする使い方なら、もっと大きく見ておきます。

例として、NASの使用量が2.0TB、年に0.5TB増え、3年使う前提で、上乗せ率を1割〜2割とします。

- 3年後の使用量: `2.0 + 0.5 × 3 = 3.5TB`
- 世代を含めた必要容量: `3.5 × 1.1 ≒ 3.85TB` 〜 `3.5 × 1.2 = 4.2TB`

ここで注意したいのが、HDDの表記容量とOSが表示する容量の違いです。HDDは1TB＝10の12乗バイトで表記されますが、WindowsやNASの管理画面の多くは2の40乗バイトを1TB（正確にはTiB）として表示します。4TBのHDDは `4 × 10^12 ÷ 2^40 ≒ 3.64` で、管理画面上は約3.6TBです。NASの使用量も同じ単位で表示されるため、上の例の3.85〜4.2TBは4TBのHDDには収まらず、**バックアップ先は8TBか、少なくとも5TB以上を選ぶ**のが妥当という結論になります。

一方、使用量が1TB程度で増加も年0.2TBほどなら、`(1.0 + 0.2 × 3) × 1.2 ≒ 1.9TB` で、4TBの外付けHDDで十分です。この計算を最初にしておくと、買ってすぐ容量不足になる失敗を避けられます。

### どの構成を選ぶか

- **まずはBから始める**: 3-2-1を満たす最小の構成です。
- **持ち出したHDDを取りに行く頻度が低いならD**: 2台のポータブルHDDを交互に入れ替えるため、片方を家に持ち帰っている間も家の外にコピーが残ります。
- **使用量が3TBを超えている、または世代を多く残したいならE**: 手元側を8TBにすると履歴に余裕が出ます。ただし持ち出し側は5TBなので、NASの使用量が4TB前後を超えたら、家の外はクラウドに切り替えるのが現実的です。
- **USBでつなぐ運用が煩わしい、監視をまとめたいならC**: 2台目のNASはバックアップの成否をNAS同士で管理できます。DS223jはDSM 7.2-64570以降でBtrfsとSnapshot Replicationに対応しているため、Btrfsで作ったボリュームなら2台目側にもスナップショットで履歴を残せます（スナップショット数の上限は仕様表で確認してください）。
- **データが多く、持ち運びが現実的でないならG**: 家の外のコピーをクラウドに任せます。料金の考え方は後述します。

## 構成を決めたら選ぶ機材

外付けHDDは「NASの横につなぎっぱなしにする据え置き型」と「持ち出してローテーションするポータブル型」で役割が分かれます。据え置き型は容量単価の安さを、ポータブル型はUSBバスパワーで動き持ち運べることを優先して選びます。2台目のNASやNAS本体のディスクには、24時間稼働を前提にしたCMR方式のNAS向けHDDを使います。

## 外付けHDDへの自動バックアップを設定する

バックアップは、手動で思い出したときに取る運用では続きません。最初に自動化しておくことが大切です。

### Synology：Hyper Backup で世代付きバックアップ

Synology のNASでは、パッケージセンターから入れる「Hyper Backup」が基本の選択肢です。外付けHDDのほか、別のSynology NASやクラウドストレージもバックアップ先に選べます。大まかな流れは次のとおりです（メニューの表記はDSMのバージョンや表示言語で異なる場合があります）。

1. 外付けHDDをNASのUSBポートにつなぎ、コントロールパネルの外部デバイスの画面で認識を確認する。NTFSで出荷されたHDDは、ここでNAS向けのファイルシステム（ext4など）に再フォーマットしておくと扱いやすい（中身はすべて消えます）。
2. Hyper Backup を開き、新しいデータバックアップタスクを作成する。バックアップ先に「ローカルフォルダとUSB」を選び、つないだ外付けHDDを指定する。
3. バックアップするフォルダを選ぶ。写真・書類・仕事のデータなど、失うと困る共有フォルダから順に選び、Dockerのキャッシュや再ダウンロードできるメディアは外すと容量を節約できる。
4. スケジュールを毎日、NASを使わない深夜の時間帯に設定する。
5. バックアップのローテーション（世代管理）を有効にし、残す世代数を決める。Smart Recycle を選ぶと、古い世代を一定の規則で間引きながら長い期間の履歴を残せる。
6. 整合性チェックを定期的に実行する設定にしておく。

Hyper Backup の保存先には、元のファイルがそのままの形では並ばず、バックアップ用のデータとして保存されます。中身を確認したり特定のファイルを戻したりするときは、Hyper Backup の復元機能か、PCで使える Hyper Backup Explorer を使います。**設定したら一度、適当なファイルを実際に復元してみる**ところまでやって初めて完了です。

### Synology：USB Copy で手軽にコピー

もう1つの選択肢が「USB Copy」パッケージです。NASのフォルダをUSBの外付けHDDへコピーする機能で、コピー方式として「増分」「ミラー」「複数バージョン」などを選べます。保存先にはファイルがそのままの形でコピーされるので、外付けHDDをPCにつなげば中身を直接開ける点が利点です（NAS向けに再フォーマットしたHDDはWindowsで直接読めない点に注意）。

方式の選び方は次のように考えます。

| USB Copyのコピー方式 | 動き | バックアップとしての評価 |
|---|---|---|
| ミラー | 元と同じ状態にそろえる。元で消すとコピー先からも消える | 誤削除・ランサムウェアには弱い |
| 増分 | 追加・変更されたファイルをコピーし、元で消してもコピー先には残る | 誤削除には強いが、上書きされた古い版は残らない |
| 複数バージョン | コピーのたびに版を残す | 世代管理ができ、バックアップ向き |

**ミラー方式はバックアップではなく同期**だと考えてください。消した、暗号化された、という変更まで忠実にコピーしてしまうからです。持ち出し用のポータブルHDDに丸ごとコピーを作る用途ならUSB Copy、毎日の世代付きバックアップならHyper Backup、という使い分けがわかりやすいでしょう。

### Linux（自作NAS・ミニPC）：rsync＋cron で世代管理

UbuntuやDebianで組んだ自作NAS・ミニPCなら、`rsync` の `--link-dest` オプションを使うと、変更のないファイルをハードリンクで共有しながら日付ごとの世代を残せます（TrueNASやUnraidは /etc の手動編集が再起動で消えるため、TrueNASならGUIのRsync TasksとCron Jobs、Unraidならプラグインでの設定が前提になります）。変更のないファイルは容量をほとんど消費しないため、外付けHDDでも数十世代を持てます。

まず外付けHDDを決まった場所に自動でマウントします。`lsblk -f` でUUIDを確認し、`/etc/fstab` に追記します。

```bash
# 新しいHDDをext4でフォーマットする（/dev/sdX1 は必ず lsblk で確認。中身はすべて消える）
sudo mkfs.ext4 -L usb-backup /dev/sdX1
sudo mkdir -p /mnt/usb-backup
lsblk -f   # usb-backup のUUIDを控える
```

`/etc/fstab` には次の1行を追記します（`nofail` を付けると、HDDを外していても起動が止まりません）。

```
UUID=控えたUUID  /mnt/usb-backup  ext4  defaults,nofail  0  2
```

```bash
# /etc/fstab を編集して上の1行を追記したら、再起動せずにマウントして確かめる
sudo systemctl daemon-reload && sudo mount -a && mountpoint /mnt/usb-backup
```

次に、バックアップのスクリプトを `/usr/local/bin/backup-usb.sh` として保存します。

```bash
#!/bin/bash
set -eu
SRC="/srv/data/"                 # バックアップしたいフォルダ（末尾の / に注意）
DEST_ROOT="/mnt/usb-backup"
TODAY=$(date +%F)
KEEP=30                          # 残す世代数

# HDDがマウントされていなければ中止（内蔵ディスクに書き込む事故を防ぐ）
mountpoint -q "$DEST_ROOT" || { echo "backup disk is not mounted"; exit 1; }

# バックアップ元が空なら中止（元ディスクが外れた日に空の世代で古い世代を押し出す事故を防ぐ）
[ -n "$(ls -A "$SRC")" ] || { echo "source is empty"; exit 1; }

# 前回分とのハードリンクで、変更のあったファイルだけを新たに保存する
rsync -aH --delete --link-dest="$DEST_ROOT/latest" "$SRC" "$DEST_ROOT/$TODAY/"
ln -sfn "$DEST_ROOT/$TODAY" "$DEST_ROOT/latest"

# 古い世代を削除（日付名で並べ、新しい $KEEP 個だけ残す）
ls -1d "$DEST_ROOT"/20??-??-?? | head -n -"$KEEP" | xargs -r rm -rf
```

実行権限を付けて、cronで毎日深夜に動かします。

```bash
sudo chmod +x /usr/local/bin/backup-usb.sh
sudo crontab -e
# 毎日 3:30 に実行し、結果をログに残す
30 3 * * * /usr/local/bin/backup-usb.sh >> /var/log/backup-usb.log 2>&1
```

初回は `latest` がないため `--link-dest` の警告が出ますが、全量のコピーとして正常に動きます。`--delete` を付けても、消したファイルは過去の日付フォルダに残るので、30世代以内なら戻せます。

初回のバックアップにかかる時間も見積もっておきましょう。USB 3.0接続のHDDへの書き込みが仮に毎秒120MBで続いたとすると、2TBでは `2,000,000MB ÷ 120MB/s ≒ 16,700秒 ≒ 約4.6時間` です。実際の速度はHDDやファイルの大きさで変わり、細かいファイルが多いともっと遅くなります。2台目のNASへLAN経由で送る場合も、1GbEの理論値は毎秒125MBなので、同じくらいの時間が目安になります。

## オフサイトの選択肢：持ち出しローテーションかクラウドか

### ポータブルHDDのローテーション

もっとも費用が読みやすいのが、ポータブルHDDを実家や職場に預け、定期的に持ち帰って最新の状態に更新する方法です。ここで決めるべきなのは入れ替えの間隔で、**家の外のコピーが古くなる分だけ、家ごと失う事故のときに戻らないデータが増えます**。

1日に増えるデータを2GB（スマホ写真や動画を家族で撮る程度の仮定）として計算すると、次のようになります。

| 入れ替えの間隔 | 家の外のコピーの古さ（最大） | 戻らないデータ量の目安（2GB/日） |
|---|---|---|
| 1週間 | 7日 | 2GB × 7日 ＝ 14GB |
| 2週間 | 14日 | 2GB × 14日 ＝ 28GB |
| 1か月 | 30日 | 2GB × 30日 ＝ 60GB |
| 3か月 | 90日 | 2GB × 90日 ＝ 180GB |

ただしこれは「家の中のコピーも含めてすべて失った場合」の数字です。ディスク故障や誤削除なら、毎日更新している外付けHDDから戻せます。家ごと失う事故はめったに起きないので、**実家に行く頻度に合わせて1か月ごと**くらいが、手間とのバランスが取りやすい落としどころです。

ポータブルHDDが1台だけだと、持ち帰って更新している間は家の外にコピーがありません。その間に家ごと失う事故が起きれば、持ち帰ったHDDも含めてすべてを失います。2台を交互に使う構成D・Eなら、1台を持ち帰るときにもう1台が家の外に残ります。持ち出すHDDは紛失のリスクもあるため、Hyper Backup のクライアント側暗号化を使うか、暗号化したうえでコピーしておくと安心です。

### クラウドに送る場合の確認項目

持ち運びの手間をなくしたい、データが多くてポータブルHDDに収まらない、という場合はクラウドが候補になります。料金は各社の公開価格で決まり、改定もあるため、ここでは具体的な金額は挙げず、比べるときに見るべき性質をまとめます。

| 種類 | 例 | 料金の仕組み | 確認したい点 |
|---|---|---|---|
| 個人向けクラウドストレージ | Google ドライブ、OneDrive、Dropbox など | 容量ごとの定額プラン | 同期型だと削除や暗号化も同期される。NASのバックアップ先として対応しているか |
| オブジェクトストレージ | Amazon S3 や S3互換のサービス | 保存した容量に応じた従量課金が中心 | ダウンロード（転送）料金の有無、最低保存期間、APIリクエスト料金 |
| NASメーカーのクラウド | Synology C2 Storage など | プランごとの容量課金 | 対応するNASのバックアップ機能との連携、世代管理の扱い |

特に見落としやすいのが、**取り出すときの料金**です。保存するだけなら安くても、NASが全損して数TBを一度にダウンロードすると、転送料金がかかるサービスがあります。また、保存期間に下限があるサービスでは、世代を短期間で削除しても最低期間分の料金がかかります。契約前に、各社の公開している料金ページで「保存料金」「転送料金」「最低保存期間」の3点を確認してください。

手元のHDDとクラウドの費用を比べるときは、次の式で損益分岐点を出せます。

```
損益分岐の月数 ＝ 持ち出し用HDDの価格 ÷ クラウドの月額
```

たとえば、仮に月額1,000円だとすると（料金を示すものではない仮の値です。実際の月額は保存する容量とサービスで大きく変わります）、ポータブルHDD 5TB 1台の34,800円は `34,800 ÷ 1,000 ≒ 35か月` で、約3年でクラウドのほうが割高になる計算です。ただしクラウドには「持ち運ぶ手間がない」「毎日自動で家の外のコピーを更新できる」という、HDDでは得られない利点があります。前述の入れ替え表でいえば、間隔を1日にできるということです。

自作NASからクラウドへ送るなら、暗号化と世代管理を備えた `restic` や、さまざまなクラウドに対応した `rclone` が定番です。

```bash
# restic でS3互換ストレージに暗号化バックアップする例（接続情報は環境変数で渡す）
export RESTIC_REPOSITORY="s3:https://エンドポイント/バケット名"
export AWS_ACCESS_KEY_ID="アクセスキー"
export AWS_SECRET_ACCESS_KEY="シークレットキー"
export RESTIC_PASSWORD_FILE=/root/.restic-pass
restic init                                  # 初回のみ
restic backup /srv/data
restic forget --keep-daily 7 --keep-weekly 4 --keep-monthly 6 --prune
```

`RESTIC_PASSWORD_FILE` のパスワードを失うと、バックアップは二度と復号できません。NASの外、たとえばパスワード管理ツールにも控えておいてください。

## ランサムウェアと誤削除に備える：世代管理とスナップショット

3-2-1ルールの「コピーの数」と同じくらい大事なのが、**いつの時点に戻せるか**です。最新の状態しか持たないバックアップは、暗号化されたファイルや消したファイルで上書きされた時点で役に立たなくなります。

- **スナップショットを有効にする**: Btrfs（Synologyの対応機種）やZFS（TrueNAS）では、ボリュームの状態を瞬時に記録できます。1日ごと〜数時間ごとに取得し、2〜4週間残す設定が目安です（共有フォルダあたりのスナップショット数には機種ごとに上限があるため、取得間隔と保持期間を掛け算して確認します）。誤削除にはこれが最も速く効きます。ただしNAS本体のディスク上にあるため、NASが壊れれば一緒に失われます。
- **バックアップの世代は長めに残す**: ランサムウェアは、暗号化されてから気づくまで時間がかかることがあります。毎日1世代を7日分しか残さないと、気づいたときには全世代が暗号化後の状態、ということが起こりえます。日次を数週間分、月次を数か月分のように、古い時点も間引いて残すのが基本です。
- **管理者アカウントを分ける**: 普段のファイル操作に管理者アカウントを使わず、2段階認証を有効にしておくと、スナップショットやバックアップ設定まで消される事態を防ぎやすくなります。

停電や瞬断でNASが異常終了すると、ファイルシステムやバックアップのデータそのものが壊れることがあります。24時間動かすNASには、[自宅サーバーのUPS（無停電電源）おすすめと選び方](/articles/homelab-ups-osusume-2026/) で紹介しているような自動シャットダウン連携も、バックアップと同じ「データを守る仕組み」として検討してください。

## つまずきポイント

- **外付けHDDが外れたまま気づかない**: USBの抜けやHDDの故障で、何週間もバックアップが失敗していることがあります。Hyper Backup の通知やメール通知を有効にし、失敗時に知らせが来るようにしておきます。
- **NASの使用量がバックアップ先の容量を超える**: 最初は収まっていても、数年で逆転します。Hyper Backup の Smart Recycle は古い世代を間引いてくれますが、最新の1世代すら入らなくなれば失敗します。年に1回、使用量とバックアップ先の空きを見比べる習慣をつけます。
- **復元を一度も試していない**: 暗号化のパスワードや復元手順がわからなければ、事故のときに戻せません。半年に1回程度、適当なフォルダを別の場所に復元して確かめます。
- **Immichなどのアプリのデータベースを忘れる**: 写真のファイルだけをコピーしても、アルバムや顔認識の情報はデータベース側にあります。アプリごとのバックアップ手順は [Immichで自宅サーバーにGoogleフォト代替を構築する完全ガイド2026](/articles/immich-selfhosted-google-photos-alternative-guide/) の「バックアップは2種類必要」を参照してください。

## やらなくていい人・過剰になるケース

3-2-1ルールは強力ですが、すべてのデータに必要なわけではありません。次のような場合は、もっと軽い構成で十分なことがあります。

- **NASの中身が、ほかに元があるデータだけ**: 購入した動画や音楽、再ダウンロードできるソフトのインストーラー、ほかのPCの作業用コピーだけなら、失っても取り戻せます。バックアップの対象から外すか、外付けHDD1台（構成A）で十分です。
- **写真や書類がすでにクラウドにも保存されている**: スマホの写真がクラウドの写真サービスにも残っていて、NASは「手元の2つ目のコピー」という位置づけなら、NAS＋クラウドで家の外のコピーは確保されています。外付けHDDを足せば3つになります。
- **データ量がごく少ない**: 大事なデータが数百GB程度なら、NASの外付けHDDに加えて、大容量のUSBメモリやPCの内蔵ディスクにもコピーを置くだけで、媒体を分ける目的は果たせます。新たにポータブルHDDを2台買う構成D・Eは過剰になりがちです。
- **費用をかけすぎている**: 家族写真のNASに、2台目NAS＋ポータブルHDD2台＋クラウドまで重ねると、守りたいデータの価値に対して費用と手間が大きくなりすぎます。3-2-1を一度満たしたら、それ以上の追加は「本当に失うと困るデータか」で判断してください。

## よくある質問

**Q. RAID 1にしていれば、外付けHDDは要りませんか？**
要ります。RAID 1は2台のディスクに同じ内容を同時に書くため、誤削除やランサムウェアの被害も両方に反映されます。RAIDはディスク故障で止まらないための仕組みで、過去の状態に戻すことはできません。

**Q. 外付けHDDはNASにつなぎっぱなしで大丈夫ですか？**
毎日の自動バックアップのためには、つなぎっぱなしが現実的です。ただし、常時接続のHDDはNASと一緒にランサムウェアの被害を受ける可能性があり、落雷などでNASと同時に壊れることもあります。その弱点を補うのが、ネットから切り離した持ち出し用HDDやクラウドの役割です。

**Q. クラウドに全部預ければ、外付けHDDは不要ですか？**
NAS＋クラウドでコピーは2つ、家の外のコピーも確保できますが、3つにはなりません。また、NASが全損したときに数TBをダウンロードすると、回線速度によっては何日もかかり、転送料金がかかるサービスもあります。手元に外付けHDDがあれば、普段の誤削除やディスク故障はすぐに戻せます。

**Q. 外付けHDDはNAS用HDDのような専用品でなくてもよいですか？**
毎日数十分〜数時間だけ書き込む用途なら、一般的な外付けHDDで問題になりにくいです。NAS本体や2台目のNASのように24時間動かし続けるディスクには、CMR方式のNAS向けHDDを選びます。

## まとめ

- **RAIDはバックアップではない**。止まらないための仕組みで、誤削除・ランサムウェア・本体故障・火災には効かない
- 3-2-1ルールは、コピー3つ（元データ込み）、別の筐体2つ以上、1つは家の外
- 必要容量は「（使用量＋年間増加×年数）×1.1〜1.2」で計算し、4TBのHDDはOS上で約3.6TBになる点を見込む
- NASがあるなら、外付けHDD 4TB＋ポータブルHDD 5TBの構成Bで、約6.8万円から3-2-1を満たせる
- 自動化はSynologyならHyper Backup、自作NASならrsync＋cron。設定したら必ず一度復元を試す
- クラウドは保存料金だけでなく、転送料金と最低保存期間を各社の公開価格で確認する
