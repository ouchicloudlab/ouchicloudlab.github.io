## 「HDDケース＋ミニPC」はNAS代わりになるのか

自宅サーバー用のミニPCを動かしていると、「HDDを何台か入れられるUSBケースをつなげば、NASを買わなくて済むのでは」と考えるのは自然な流れです。2〜4台用のHDDケースは2万円前後から手に入り、市販NASより安く見えます。

結論から言うと、**ファイルを置く場所としてはNAS代わりになりますが、NASが自動でやってくれることの多くを自分で組み立てる必要があります**。共有、ディスクの監視、冗長化、スナップショット、スリープの制御などです。そしてUSB接続には、内蔵SATAやNASにはない「切断」という弱点があり、ZFSやソフトウェアRAIDと組み合わせるときに問題になりやすい点も押さえておく必要があります。

この記事では、NASとの違いと台数別の総額を整理したうえで5製品を比較し、LinuxのミニPCでの設定例までまとめます。

## USB接続のHDDケース（DAS）とNASの違い

USBやThunderboltでPCに直接つなぐストレージは、DAS（Direct Attached Storage）と呼ばれます。ケースはあくまで「HDDの入れ物」で、つないだPCからは外付けディスクが増えたように見えるだけです。NASはそれ自体がCPUとOSを持った小さなサーバーで、LANにつなげば単体で動きます。

| 比べる点 | USB接続のHDDケース（DAS） | 市販NAS |
|---|---|---|
| 単体で動くか | 動かない。PCやミニPCにつないで初めて使える | 動く。LANにつなげば単体でファイルサーバーになる |
| ネットワーク越しの共有 | ケースにはない。つないだPC側でSambaなどを設定する | 標準機能。管理画面から共有フォルダを作るだけ |
| RAID・冗長化を担うのは | ケースのRAID機能（ある機種のみ）か、PC側のソフトウェアRAID | NASのOS（管理画面で構成） |
| スナップショット・世代管理 | PC側のファイルシステム（Btrfs・ZFSなど）で自分で組む | 対応機種なら管理画面で設定できる |
| ディスクの健康監視（SMART） | PC側で smartctl などを設定。ケースによっては取得できない | 管理画面で自動監視し、異常を通知 |
| スマホからの自動バックアップ | PC側にアプリ（Immichなど）を自分で用意する | メーカーの専用アプリが用意されていることが多い |
| 接続の安定性 | USBケーブル・ケースの抜けや再接続がありうる | ディスクは内部のSATAで直結 |
| 拡張・流用 | ケースを別のPCにつなぎ替えられる | そのNASの中で完結する |

表を縦に見ると、DASの欄は「PC側で自分で設定する」が並びます。つまりHDDケースは**NASのうち「ディスクを入れる箱」の部分だけを買う**という選択で、残りはミニPCとソフトウェアで補うことになります。Linuxやコマンド操作に慣れていて、その組み立て自体を楽しめる人には向き、管理画面で完結させたい人には向きません。

## NAS代わりになる使い方・ならない使い方

### 向いている使い方

- **ミニPCのデータ置き場**: JellyfinやImmichなど、ミニPCで動かしているアプリのメディア・写真の保存先にする。アプリと同じ機械にディスクがつながっているため、LANを経由せずに読み書きできます。
- **Sambaで共有する個人用ファイルサーバー**: ミニPCから共有フォルダを公開し、1〜2台のPCから使う。
- **バックアップの受け皿**: PCやNASのバックアップ先として、夜間だけ書き込む。
- **コールドストレージ**: 普段は電源を切っておき、必要なときだけディスクを動かして古いデータを取り出す。

### 向いていない使い方

反対に、ディスクが1台壊れても止まらずに動き続けてほしい、家族の共有ストレージにしたい、といった「NASの機能そのもの」が目的なら向きません（詳しくは後半の「やめたほうがいい人」で整理します）。また、RAIDもケースも「バックアップ」ではない点はNASと同じです。別の場所にコピーを置く考え方は [NASバックアップの3-2-1ルール実践ガイド](/articles/nas-backup-3-2-1-rule-guide/) を参照してください。

## 複数台用HDDケースの選び方

### ベイ数：今の台数＋1を目安に

ベイ数は、最初に入れる台数より1つ多いものを選ぶと、容量が足りなくなったときにケースごと買い替えずに済みます。今回の価格目安では、4台用のLHR-4BNHUC（約17,100円）が2台用のテラスハウス（約17,700円）とほぼ同じ価格のため、3台以上になる可能性があるなら最初から4台用にする判断も十分ありえます。

一方、1台用のケースを台数分並べる方法にも利点があります。ケースが1つ壊れても他のディスクは影響を受けず、交換もそのケース1つで済みます。代わりにACアダプターとUSBポートが台数分必要です。

### USB規格：Gen1とGen2の帯域を台数で割る

複数台用ケースは、すべてのディスクが1本のUSBケーブルを共有します。そのため、**USBの帯域をディスクの台数で分け合う**ことになります。

USB 3.2 Gen1（5Gbps）は8b/10b方式の符号化で、10ビットのうち8ビットがデータです。理論上のデータ転送の上限は `5Gbps × 8/10 ÷ 8 ＝ 500MB/s` になります。USB 3.2 Gen2（10Gbps）は128b/132b方式で、`10Gbps × 128/132 ÷ 8 ≒ 1,212MB/s` です。実際にはプロトコルの処理分があるため、どちらもこれより下がります。

3.5インチHDDの連続読み出しは、1台あたり200MB/s前後が目安です（回転数やディスクの内周・外周で変わります）。複数台を同時に読み出したときの合計と、USBの理論上限を比べると次のようになります。

| 同時に読み出す台数 | HDDの合計（200MB/s×台数） | Gen1（理論500MB/s） | Gen2（理論約1,212MB/s） |
|---|---|---|---|
| 1台 | 200MB/s | 余裕あり | 余裕あり |
| 2台 | 400MB/s | 上限に近い | 余裕あり |
| 3台 | 600MB/s | 上限を超える（1台あたり約167MB/sに） | 余裕あり |
| 4台 | 800MB/s | 上限を超える（1台あたり約125MB/sに） | 上限内（実効では近づく） |

ここで大事なのは、**帯域が効いてくる場面は限られる**という点です。Sambaで共有したファイルをLAN越しに読むなら、1GbEの理論値は125MB/s、2.5GbEでも約312MB/sで、Gen1の500MB/sより先にLANが頭打ちになります。

差が出るのは、全ディスクを同時に読む作業です。RAIDの再構築やZFSのスクラブ（全データの検査）がこれにあたります。4TBのHDDを全部読む時間は、1台200MB/sなら `4,000,000MB ÷ 200MB/s ＝ 20,000秒 ≒ 約5.6時間` ですが、Gen1のケースで4台を同時に読んで1台あたり125MB/sまで下がると `4,000,000 ÷ 125 ＝ 32,000秒 ≒ 約8.9時間` になります。**4台を同時に読み書きする作業（全ディスクの検査や一括コピーなど）が多いならGen2**、1〜2台を個別に使うならGen1でも十分、と考えるとよいでしょう。なお、ケース内部の接続方式によっては、合計の速度がUSB規格の上限より低くなることもあり、この点は商品ページだけでは判断できません。

### 電源連動機能：24時間サーバーでは「切れないか」を確認

電源連動機能は、PCの起動と終了に合わせてケースのHDDとファンを入れたり切ったりする機能です。今回の5製品では、LHR-4BNHUCとカプセルホテル Ver.3に記載があります。普段使いのデスクトップPCなら、PCを切るたびにHDDも止まるので便利な機能です。

24時間動かすサーバーにつなぐ場合は、事情が変わります。PCが動き続けるので連動は基本的に働かないはずですが、機種や設定の組み合わせによっては、OSのUSB省電力（オートサスペンド）をきっかけにケースが電源を落としたように振る舞う、といった症状が報告されることがあります。サーバー用途では、**連動機能を切り替えられるか、切り替えられない場合にどう動くか**をマニュアルで確認してから選ぶのが安全です。今回の商品ページでは、連動をオフにできるかどうかまでは確認できませんでした。

### 独立電源スイッチ：使うディスクだけを動かす

カプセルホテル Ver.3は、ドライブごとに電源スイッチを備えています。月に1回だけバックアップを取るディスクや、古いデータを保管したディスクを、普段は止めておけます。動かさないディスクは消耗も電気代も抑えられます。常時動かす2台と、たまに使う2台を1つのケースに同居させたい場合に向く機能です。

### 冷却ファン：4台なら大きめのファンを

HDDは温度が上がると寿命に影響するとされ、複数台を詰めて入れるケースでは冷却が重要です。今回の製品では、ゲートハウスが92mmファン（最大1,800rpm）、テラスハウスが6cm角ファン、LHR-4BNHUCがHDD温度に応じて3段階で回転を変える自動ファンを備えています。寝室や書斎に置くなら、回転数が温度で変わるタイプのほうが静かな時間を作りやすいでしょう。

### ケース側RAIDとソフトウェアRAIDの向き不向き

| 比べる点 | ケース側RAID | ソフトウェアRAID（mdadm・ZFSなど） |
|---|---|---|
| 設定の手軽さ | ケースのスイッチや専用ツールで設定 | Linuxのコマンドで構成 |
| ケースが壊れたとき | 同じ機種のケースがないと読めない場合がある | 別のケースや内蔵SATAにつなぎ替えて読める |
| ディスクの状態の見え方 | PCからは1台のディスクに見え、個別の状態が分かりにくい | 1台ずつ見えるので、SMARTや異常を個別に確認できる |
| USBの切断への強さ | ケース内部で完結するため、PCとの切断の影響は受けにくい | 切断でディスクが外れたと判断され、アレイが劣化扱いになりうる |
| 向いている人 | WindowsやMacで、とにかく簡単に冗長化したい | Linuxで管理でき、ケースの故障時にも読み出したい |

商品ページで確認できた範囲では、今回の5製品でRAID機能の記載があるのはテラスハウスだけです。それ以外は、各ディスクがPCから個別に見える前提で使い方を考えます。

## つまずきポイント

### USB接続でのZFS・ソフトウェアRAID

USBは、ケーブルの接触、ケースの電源、ホスト側のUSBコントローラーなどが原因で、一瞬切れて再接続されることがあります。デスクトップで1台の外付けHDDを使う分には気づかない程度でも、ZFSやmdadmはディスクが応答しなくなった時点で「故障した」と判断し、プールやアレイを劣化（デグレード）扱いにすることがあります。再接続されても自動では元に戻らず、復帰の操作と再同期が必要になる場合があります。

TrueNASの公式ハードウェアガイドは、USB接続のHDDをメインのストレージに使うのは避け、使うとしてもごく簡単なバックアップ程度にとどめるよう案内しています。USB接続ではディスクのシリアル番号が正しく伝わらず、区別できなくなる場合があるという注意もあります。ZFSを使いたいなら、SATAポートを持つ機械か市販NASを選ぶほうが無難です。どうしてもUSBで冗長化したい場合は、ディスクを1台ずつext4などで使い、定期的にパリティを計算するSnapRAIDのような方式を選ぶ人もいます。リアルタイムに同期しないぶん、一時的な切断の影響を受けにくい考え方です。OSの選び方は [TrueNAS・Unraid・Proxmox比較2026](/articles/truenas-unraid-proxmox-comparison-2026/) も参照してください。

### ケースのRAIDはケースと一体

ケース側RAIDで作ったディスクの並びは、そのケースの方式で書き込まれます。ケースが故障したとき、別のケースやPCに直接つないでも読めず、同じ機種のケースが必要になる場合があります。ケース側RAIDを使うなら、バックアップを別に取ることが前提です。

### SMARTが取れない、シリアル番号が見えない

USBのケースは、HDDとPCの間で信号を変換する部品を挟んでいます。この部品がSMART情報をそのまま渡さない機種では、ディスクの健康状態をPCから確認できません。また、PCにケース側の名前やシリアル番号が見え、どのベイのディスクか区別しにくいこともあります。導入したら、まず全ディスクのSMARTとシリアルが見えるかを確かめます。

### 勝手にスリープして、アクセスのたびに待たされる

ケースやHDDの省電力機能でディスクが止まり、アクセスのたびに回転が上がるまで数秒待たされることがあります。反対に、スピンダウンを頻繁に繰り返すとHDDの消耗につながるとも言われます。メディアのように毎日アクセスするディスクは止めず、たまにしか使わないディスクだけ止める、というように使い分けます。

## LinuxのミニPCにつなぐ設定例

Ubuntu・Debian系を前提にした例です。**ディスクを初期化するコマンドは、対象を取り違えると別のディスクのデータが消えます**。必ず `lsblk` で確認してから実行してください。

### 1. ディスクを確認する

```bash
# TRAN列が usb のものがケースのディスク。MODELとSERIALでどのHDDか確かめる
lsblk -o NAME,SIZE,MODEL,SERIAL,TRAN,FSTYPE,UUID

# 再起動で sda/sdb の順番が入れ替わっても変わらない名前
ls -l /dev/disk/by-id/ | grep usb-
```

`/dev/sda` のような名前は、起動のたびや再接続で変わることがあります。SMARTの確認やスピンダウンの設定には `/dev/disk/by-id/` の名前を、マウントにはファイルシステムのUUIDを使うと取り違えを防げます。

### 2. フォーマットとfstabへの登録

```bash
# 中身はすべて消える。/dev/sdX は lsblk で確認したものに置き換える
sudo parted /dev/sdX --script mklabel gpt mkpart primary ext4 0% 100%
sudo mkfs.ext4 -L data1 /dev/sdX1
sudo mkdir -p /srv/data1
sudo blkid /dev/sdX1   # UUID を控える
```

`/etc/fstab` に次の1行を追記します。`nofail` を付けると、ケースの電源が入っていなくてもミニPCの起動が止まりません。`x-systemd.device-timeout` は、ディスクを待つ時間の上限です。

```
UUID=控えたUUID  /srv/data1  ext4  defaults,nofail,x-systemd.device-timeout=10s  0  2
```

```bash
sudo systemctl daemon-reload && sudo mount -a && findmnt /srv/data1
```

### 3. SMARTを確認する

```bash
sudo apt install smartmontools
# USB接続ではSATの指定が必要なことが多い
sudo smartctl -d sat -a /dev/disk/by-id/usb-（確認した名前）
```

エラーになる場合は、ケースがSMARTの受け渡しに対応していない可能性があります。取得できるなら、`smartd` で定期的に監視し、異常があれば通知されるようにしておきます。

### 4. スピンダウンを設定する

```bash
# 30分アクセスがなければ止める（241は30分を表す値。1〜240は5秒単位）
sudo hdparm -S 241 /dev/disk/by-id/usb-（確認した名前）
```

`hdparm -S` の設定は再起動やケースの電源の入れ直しで消えることが多いため、続けて使うなら次の `hd-idle` のように常駐する方法が確実です。また、ケースによっては `hdparm -S` が効きません。その場合は `hd-idle` を使います。パッケージのバージョンで設定ファイルの書式が異なるため、`/etc/default/hd-idle` 内のコメントを確認してください。一般的には次のように、全ディスクの既定を無効（`-i 0`）にしたうえで、止めたいディスクだけ秒数を指定します。

```
HD_IDLE_OPTS="-i 0 -a /dev/disk/by-id/usb-（確認した名前） -i 1800"
```

Debian・Ubuntuのパッケージでは、同じファイルの `START_HD_IDLE=true` を有効にしてから `sudo systemctl restart hd-idle` で反映させます（バージョンによってはこの行が無い場合もあります）。

`smartd` の定期チェックで止めたディスクが起きてしまう場合は、`/etc/smartd.conf` の該当行に `-n standby` を付けると、止まっている間はチェックを飛ばします。ZFSやRAIDに組んだディスクは、スピンダウンさせないのが基本です。

### 5. Sambaで共有する（最小設定）

```bash
sudo apt install samba
sudo smbpasswd -a ユーザー名   # Linuxに存在するユーザーにSamba用のパスワードを設定
sudo chown ユーザー名: /srv/data1
```

マウント後に `sudo chown ユーザー名: /srv/data1` を実行し、共有フォルダの持ち主をSambaで使うユーザーにしておきます。rootのままだと書き込めません。

`/etc/samba/smb.conf` の末尾に次を追記します。

```
[data1]
   path = /srv/data1
   read only = no
   valid users = ユーザー名
```

```bash
testparm                       # 設定の書き間違いを確認
sudo systemctl restart smbd
```

WindowsからはエクスプローラーのアドレスバーにミニPCのIPアドレスを `\\192.168.x.x\data1` の形で入力して開きます。家の外から使いたい場合も、Sambaのポートをルーターで開けるのは避け、VPN経由にしてください。

## やめたほうがいい人

次に当てはまるなら、HDDケースではなく市販NASを選ぶほうが満足しやすいはずです。

- **家族が同時にアクセスする**: 複数人の写真・書類を集める場所は、ユーザー管理や権限設定が管理画面で完結するNASのほうが運用しやすい。
- **スマホから自動でバックアップしたい**: NASメーカーの専用アプリに任せたいなら、自前でアプリを用意する構成は手間が大きい。
- **ミニPCをまだ持っていない、ファイル置き場だけが目的**: 総額の計算どおり、市販NASのほうが安くなる。
- **Linuxの設定を自分で直す時間がない**: USBの切断、ディスクの名前の変化、Sambaの権限など、不具合の切り分けをすべて自分で行う必要がある。
- **データをそのケースにしか置かない**: USBケースは切断やケース故障という弱点が加わるぶん、バックアップなしでは特に危うい構成です。

## よくある質問

**Q. USB接続のHDDケースを24時間動かし続けても大丈夫ですか？**
ケース自体は、冷却が十分で電源が安定していれば常時動かす使い方もできます。入れるHDDは24時間稼働を想定したNAS向けのものを選び、ケースは冷却ファンのある機種にすると安心です。停電対策も考えるなら、ミニPCとケースをまとめてUPSにつなぎます。

**Q. 市販NASのUSBポートにHDDケースをつないで容量を増やせますか？**
多くのNASは、USBの外付けディスクをバックアップ先や追加の共有フォルダとして扱えます。ただし、NAS内部のRAIDに組み込めるとは限りません。複数台用ケースに対応しているかは、NASメーカーの互換性情報で確認してください。

**Q. ケースからHDDを取り出して、PCに直接つなげば読めますか？**
ケースのRAIDを使わず1台ずつ使っていれば、一般的には別のケースやPCのSATAポートにつないでも読めます。ケース側RAIDで構成した場合は、同じ機種のケースが必要になることがあります。

**Q. 1台用のケースを4つ並べるのと、4台用ケース1つでは、どちらがいいですか？**
費用は1台用×4（約8,000円）のほうが安く、ケースが1つ壊れても影響はそのディスクだけです。4台用は配線とUSBポートが1つで済み、設置場所もまとまります。ミニPCのUSBポートの数とACアダプターを置く場所で決めるとよいでしょう。

**Q. Raspberry Piにつないでもいいですか？**
つなぐことはできます。その場合、3.5インチHDDはPi本体のUSB給電では動かせないため、今回の製品のようにケース側に電源（ACアダプターや内蔵電源）があるものを選びます。Docker・メディアサーバーも同時に動かすなら、処理性能に余裕のあるミニPCのほうが扱いやすいでしょう。

## まとめ

- USBのHDDケースは「NASのうちディスクを入れる箱」だけ。共有・監視・冗長化はミニPC側で組み立てる
- 総額で安くなるのは、ミニPCがすでにある場合。新しく買うなら、ファイル置き場だけが目的なら市販NASのほうが安い
- 1〜2台を個別に使うならGen1でも十分。4台を同時に読み書きすることが多いならGen2を選ぶ
- 24時間サーバーでは、電源連動の動き方とSMARTが取れるかを最初に確認する
- USB接続でZFSやソフトウェアRAIDを組むのは、切断で劣化扱いになるリスクがある。冗長化よりもバックアップを優先する
