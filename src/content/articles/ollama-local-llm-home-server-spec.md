## はじめにーOllamaで自宅にAIサーバーを作る意味

Ollamaは、Llama系やMistral、GemmaなどのオープンウェイトなLLMをローカル環境で簡単に動かせるツールです。クラウドAPIと違い、通信費や利用料がかからず、社内データや個人情報を外部に送らずに済むのが最大の利点です。一方で「どのくらいのスペックがあれば動くのか」がわかりにくく、いきなり高価なGPUを買って後悔するケースも少なくありません。本記事ではモデルサイズ別に必要なスペックの目安を整理し、予算別の構成例も紹介します。

## Ollama動作に影響する4つの要素

### CPU
GPUを使わずCPUのみで推論する場合でも動作はしますが、速度は大きく落ちます。最近のミニPCに搭載されるRyzen 7000番台やCore Ultraシリーズであれば、7B程度の小型モデルなら実用的な速度で動きます。コア数よりもメモリ帯域とAVX命令のサポートが効いてくるため、極端に古いCPUは避けたいところです。

### メモリ（RAM）
モデルをGPUに載せられない場合、RAM容量がそのまま扱えるモデルサイズの上限になります。量子化（GGUF形式のQ4_K_Mなど）を使えば必要量を抑えられますが、目安として「パラメータ数（B）× 0.6〜0.8GB」程度は確保したいところです。

### GPU・VRAM
最も重要なのがVRAM容量です。モデル全体をVRAMに載せられれば、CPU推論より数倍〜数十倍速くなります。NVIDIA製GPUがOllamaでは最も安定して動作し、CUDA非対応の環境ではCPU推論にフォールバックします。

### ストレージ
モデルファイルは1つあたり数GB〜数十GBになるため、複数モデルを試すならNVMe SSDで500GB以上を目安にすると安心です。読み込み速度もSSDのほうが快適です。

## モデルサイズ別の必要スペック目安

| モデル規模 | RAM目安 | 推奨VRAM | CPUのみでの動作感 |
|---|---|---|---|
| 7B（Llama3 8B, Mistral 7Bなど） | 8〜16GB | 6GB前後 | 実用可能な速度 |
| 13〜14B | 16〜32GB | 10〜12GB | やや遅いが待てる範囲 |
| 30〜34B | 32〜64GB | 24GB前後 | 待ち時間が長く不向き |
| 70B | 64GB以上 | 48GB以上 | 実用には厳しい |

量子化レベル（Q4_K_M、Q5_K_Mなど）を下げるほど必要メモリは減りますが、応答品質もわずかに落ちます。まずはQ4_K_Mから試すのが定番です。

## 速度の目安：どれくらい待つことになるのか

スペック表よりも、実際の**体感速度**の方が判断材料になります。生成速度は「トークン/秒（tok/s）」で表され、日本語ではおおよそ1トークン＝1文字前後です。

| 速度 | 体感 |
|---|---|
| 30 tok/s 以上 | **読む速度より速い**。ストレスなく使える |
| 15〜30 tok/s | 十分実用的。会話用途で違和感は少ない |
| 5〜15 tok/s | やや待つ。長文生成はつらい |
| 5 tok/s 未満 | **実用は厳しい**。動作確認レベル |

構成別のおおまかな目安は次のとおりです（7B〜8Bクラスの4bit量子化モデルの場合）。

| 構成 | 目安速度 |
|---|---|
| N100級ミニPC（CPU推論） | 3〜6 tok/s |
| Ryzen 7000番台・Core Ultra（CPU推論） | 8〜15 tok/s |
| VRAM 8GBのGPU（モデル全体をVRAMに載せる） | 40〜70 tok/s |
| VRAM 24GBのGPU | 70〜120 tok/s |

**最も重要なのは「モデル全体がVRAMに収まるかどうか」**です。VRAMに載りきらず一部がRAMにあふれると、速度は数分の1に落ちます。VRAM 8GB と 6GB の差が、体感で数倍になることも珍しくありません。

### CPU推論はメモリ帯域で決まる

GPUを使わない場合、速度を決めるのは**コア数ではなくメモリ帯域**です。生成のたびにモデル全体をメモリから読み出すため、帯域が上限になります。

そのため、CPU推論では以下が効きます。

- **デュアルチャネル構成にする**（メモリ2枚挿し）。1枚挿しだと帯域が半減し、速度もほぼ半分になります
- より高速なメモリ規格（DDR5）を選ぶ

**メモリを1枚だけ挿している場合、2枚に増やすだけで速度が倍近くなることがあります。** GPUを買う前に確認する価値がある項目です。

## 実際に動かしてみる

導入自体は数分で終わります。

```bash
# Linux へのインストール
curl -fsSL https://ollama.com/install.sh | sh

# モデルをダウンロードして対話を開始
ollama run llama3.1:8b

# 使えるモデルの一覧を確認
ollama list
```

他のPCやスマホからAPI経由で使いたい場合は、待ち受けアドレスを変更します。

```bash
# systemd の環境変数に追加（LAN内から接続できるようにする）
sudo systemctl edit ollama
# [Service]
# Environment="OLLAMA_HOST=0.0.0.0"

sudo systemctl restart ollama
```

API はHTTPで叩けます。

```bash
curl http://192.168.1.10:11434/api/generate -d '{
  "model": "llama3.1:8b",
  "prompt": "自宅サーバーの利点を3つ挙げて",
  "stream": false
}'
```

**注意**：`OLLAMA_HOST=0.0.0.0` は認証なしでAPIを公開します。**必ずLAN内に限定し、インターネットへポート開放しないでください。** 外出先から使いたい場合は [Tailscale](/articles/tailscale-home-server-remote-access-2026/) を経由させます。

ブラウザから ChatGPT のようなUIで使いたい場合は、**Open WebUI** をDockerで追加するのが定番です。会話履歴の保存や複数モデルの切り替えができるようになります。

## 予算別の構成例

### 入門・お試し構成（3〜7万円台）

省電力ミニPC＋メモリ16GBの構成でも、7Bクラスの量子化モデルをCPU推論で試せます。速度は 3〜10 tok/s 程度で、**「読みながら待つ」感覚**です。要約や短い質問なら十分実用になります。

すでに自宅サーバーを持っているなら、**追加投資ゼロで試せる**のがこの構成の利点です。まずはここから始めて、速度に不満が出てから次を考えるのが失敗しません。

### 実用ライン（10〜20万円台）

VRAM 8GB以上のGPUを積んだ構成なら、7B〜13Bモデルをほぼリアルタイムに近い速度で使えます。ここで初めて「普段使いできる」感覚になります。

ただし自宅サーバーとして常時起動する場合、**排熱・電源容量・騒音**の3点に余裕を持たせてください。GPU搭載機は省電力ミニPCとは別物と考えた方がよく、静音性を重視するなら設置場所も検討が必要です。

### 本格運用（30万円以上）

VRAM 24GB前後のGPUがあれば、30Bクラスまで快適に動かせます。70Bクラスを本格的に使うなら複数GPUやVRAM 48GB以上のカードが視野に入りますが、**自宅サーバー用途としては電気代・排熱・騒音の負担が大きく**、費用対効果は慎重に判断すべき領域です。

## 電気代とコストの現実

このサイトの主題である「24時間稼働のコスト」で見ると、GPU搭載機は他の自宅サーバー用途とは事情がまったく異なります。

| 構成 | アイドル電力 | 月額の電気代 | 年額 |
|---|---|---|---|
| 省電力ミニPC（CPU推論） | 約10W | 約223円 | 約2,678円 |
| GPU搭載機（アイドル時） | 50〜80W | 1,116〜1,786円 | 13,392〜21,427円 |
| GPU搭載機（推論中・瞬間） | 250〜450W | — | — |

**GPU搭載機を24時間つけっぱなしにすると、アイドルだけで年間1.3〜2.1万円**かかります。これは自宅サーバーの他の用途と比べて桁が違います。

現実的な対策は次の3つです。

1. **使うときだけ起動する**（Wake-on-LAN で外部から起動）
2. **CPU推論機とGPU機を分ける**（常時稼働は省電力機、GPU機は必要時のみ）
3. **アイドル時にGPUが低電力ステートへ落ちる構成にする**

### クラウドAPIと比べて元は取れるのか

正直に書くと、**金銭面だけで判断するなら、多くの個人利用ではクラウドAPIの方が安く済みます**。

理由は単純で、個人の利用頻度では従量課金の総額が小さく、一方でGPU搭載機は本体10〜30万円＋年1〜2万円の電気代がかかるためです。損益分岐に達するには、相当な量を継続的に処理する必要があります。

それでもローカルLLMを選ぶ理由は、**コスト以外の部分**にあります。

- **データを外部に送信しない**（個人情報や社外秘を扱う場合の必須条件になり得る）
- **利用量を気にせず回せる**（大量のファイルを一括処理する用途では効いてくる）
- **サービス終了・仕様変更・値上げの影響を受けない**
- **オフラインで動く**
- **モデルを自由に選べる・差し替えられる**

**「安く済ませたい」が動機なら期待とずれます。「外に出したくないデータがある」「大量に回したい」「仕組みを触りたい」が動機なら、十分に価値があります。**

## 運用時に気をつけたいポイント

- **量子化モデルから試す**：フルサイズより先に4bit量子化版（Q4_K_M）で動作確認し、必要スペックを見極めてからハードに投資するのが失敗しにくい進め方です。
- **モデルファイルの容量に注意**：1モデルあたり4〜40GB。いくつか試すとすぐに数百GBになります。NVMe SSDで500GB以上を確保しておくと安心です。
- **APIをインターネットに公開しない**：Ollama のAPIには認証機構がありません。VPN経由でのみアクセスできるようにしてください。
- **他のサービスとメモリを取り合わせない**：Immich や Jellyfin と同居させる場合、推論中にメモリを食い尽くして他が止まることがあります。同居させるなら、モデルサイズを抑えるか、メモリを潤沢に積んでください。

## よくある質問

**Q. GPUなしでも実用になりますか？**
用途によります。短い質問への応答や文章の要約なら、7Bクラスで実用範囲です。長文生成やコード生成を快適に行いたいならGPUが必要になります。**まずCPUで試してから判断する**のが確実です。

**Q. AMDのGPUやApple Siliconでも動きますか？**
動きます。Apple Silicon はメモリとGPUが統合されている構造上、大きなモデルを扱いやすいという特徴があります。AMD GPU は ROCm 経由で対応していますが、NVIDIA と比べると環境構築でつまずく場面が多いのが実情です。**安定性を優先するならNVIDIA**が無難です。

**Q. 日本語の性能はどうですか？**
モデルによって差が大きい部分です。近年のモデルは日本語対応が改善していますが、同じパラメータ数なら英語より日本語の方が品質は落ちる傾向があります。日本語での利用が主なら、**日本語対応を明記しているモデルを選ぶ**か、ワンランク上のサイズを使うと満足度が上がります。

**Q. 既存の自宅サーバーに追加できますか？**
できます。ただしメモリの空き容量を確認してください。7Bモデルで6〜8GB程度を占有するため、他のサービスと合わせて足りるかを事前に計算しておきましょう。

**Q. Proxmox上の仮想マシンで動かせますか？**
CPU推論なら問題なく動きます。GPUを使う場合は**GPUパススルー**の設定が必要で、難易度が上がります。GPUを使うなら、仮想化を挟まずベアメタルで動かす方が素直です。

## まとめ

- 速度を決めるのは **「モデル全体がVRAMに収まるか」**。あふれた瞬間に速度は数分の1に落ちる
- CPU推論では **メモリ帯域が支配的**。メモリ1枚挿しなら2枚にするだけで倍近く変わる
- 体感の目安は **15 tok/s 以上で実用、30 tok/s 以上で快適**
- **GPU搭載機の24時間稼働はアイドルだけで年1〜2万円**。使うときだけ起動する運用が現実的
- **金銭面ではクラウドAPIの方が安いことが多い**。価値はデータを外に出さないこと・使い放題・自由度にある
- APIには認証がない。**インターネットへ公開しない**
- まずは手持ちの機材＋7Bの量子化モデルで試す

段階的に進めれば、無駄な投資を避けられます。母艦選びは [自宅サーバー向けミニPCおすすめ5選](/articles/mini-pc-osusume-2026/)、外部からの安全なアクセスは [Tailscale設定ガイド](/articles/tailscale-home-server-remote-access-2026/) をご覧ください。
